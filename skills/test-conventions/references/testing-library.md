# Testing Library (Angular Testing Library, React Testing Library)

One package per framework, with the same queries and the same rules: `@testing-library/angular` (Angular Testing Library) and `@testing-library/react` (React Testing Library), both built on `@testing-library/dom`. Test a component the way the user uses it: what they see and what they do, not its internal state nor its DOM.

- **A component presents and passes things on**; its rules are tested without rendering (skill `unit-tests`, "A rule lives outside the framework"). A component test checks how a state is shown and that an action is passed on.
- **Queries, in the priority order of the Testing Library documentation ("About Queries")**: `getByRole` with its accessible name (`getByRole('button', { name: 'Save' })`), `getByLabelText`, `getByPlaceholderText`, `getByText`, `getByDisplayValue`, `getByAltText`, `getByTitle`, and `getByTestId` as a last resort. A query by role that fails often reveals an accessibility defect: fix it in the component.
- **`screen`** rather than the queries returned by `render`.
- **`getBy…`** for what must be there, **`queryBy…`** only to check an absence (`expect(screen.queryByRole('alert')).not.toBeInTheDocument()`), **`findBy…`** for what appears after an asynchronous effect (rather than `waitFor` around a `getBy…`). Inside `waitFor`, an assertion, never an action.
- **`userEvent`** (`@testing-library/user-event`) rather than `fireEvent`: `const user = userEvent.setup()`, then `await user.click(…)`, `await user.type(…)`.
- **Text**: with a string, `getByText` already matches the exact text (the whole text content, whitespace normalized); a regular expression (`/at 4/`) looks for a substring: anchor it (`/^Closes at 4$/`) when another text can extend it.
- **DOM matchers**: `@testing-library/jest-dom` with Jest or Vitest (`import '@testing-library/jest-dom/vitest'` in Vitest's setup file), `@testing-library/jasmine-dom` with Jasmine: `toBeInTheDocument`, `toBeDisabled`, `toHaveValue`…; no CSS class, no style, no internal state.
- **Dependencies**: the test gives the component a double of each dependency it uses: a stub or a fake for what it reads, a spy for what it sends. In Angular, through the `providers` of `render`; in React, through props or a context, mounted by a helper (`renderWithProviders(…)`) when several tests need the same ones. Doubling the network at the HTTP level (MSW) is for the test of the code that makes the HTTP calls, not for a component's.
- **Angular**: `render` is asynchronous: `await render(OrderSummaryComponent, { inputs: { order: anOrder() }, on: { confirmed }, providers: [{ provide: ORDERS, useValue: new InMemoryOrders() }] })`, then the same queries. `inputs` and `on` replace `componentInputs`, `componentOutputs` and `componentProperties`, now deprecated. An output is checked through the callback given to `on`, a spy (`vi.fn()`, `jasmine.createSpy('confirmed')`).
- **React**: `render(<OrderSummary order={anOrder()} />)` is synchronous. A custom hook is tested with `renderHook`; the rule it calls, without React.
